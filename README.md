# KVIMDB

**KVIMDB** — локальная in-memory key-value база данных на **C++23** с текстовым командным интерфейсом, TTL, ограничением памяти и поддержкой геопространственных запросов.

Проект реализует подмножество команд Valkey/Redis и может использоваться как встраиваемая библиотека либо как отдельное интерактивное консольное приложение.

```text
SET user:1 Alice
GET user:1
LPUSH tasks review deploy
SADD skills cpp databases algorithms
GEOADD cities 30.3141 59.9386 saint-petersburg
```

## О проекте

KVIMDB хранит данные исключительно в оперативной памяти процесса и поддерживает четыре типа значений:

- строки;
- двусвязные списки;
- множества уникальных строк;
- геопространственные коллекции.

Для каждого ключа дополнительно хранятся:

- тип значения;
- приблизительный объём занимаемой памяти;
- необязательное время истечения TTL.

Обработка команд построена через таблицу диспетчеризации: строковое имя команды связывается с отдельным обработчиком, возвращающим `std::expected<std::string, std::string>`.

## Основные возможности

| Возможность | Описание |
|---|---|
| In-memory хранение | Все данные находятся внутри процесса без внешней СУБД |
| Несколько типов данных | String, List, Set и геопространственная коллекция |
| Текстовый интерфейс | Команды читаются из `stdin`, результаты выводятся в `stdout` |
| Регистронезависимые команды | `SET`, `set` и `Set` обрабатываются одинаково |
| TTL | Ключам можно назначать ограниченное время жизни |
| Лимит памяти | Увеличивающие хранилище операции проверяются перед выполнением |
| Геопоиск | Поиск точек в радиусе и вычисление расстояния по формуле Хаверсина |
| Шаблоны ключей | `KEYS` поддерживает `*` и `?` |
| Обработка ошибок | Ошибки возвращаются через `std::expected` |
| Автоматические тесты | В репозитории находится 80 тестовых сценариев |
| CI | Проверка GCC, Clang, AddressSanitizer, UBSan и стиля кода |

## Поддерживаемые команды

### Строки

| Команда | Синтаксис | Результат |
|---|---|---|
| `SET` | `SET key value` | сохраняет строку и сбрасывает TTL |
| `GET` | `GET key` | возвращает строковое значение |
| `STRLEN` | `STRLEN key` | возвращает длину строки |
| `APPEND` | `APPEND key value` | дописывает данные в конец строки |
| `EXPIRE` | `EXPIRE key seconds` | назначает время жизни ключа |
| `TTL` | `TTL key` | возвращает оставшееся время жизни |

### Списки

| Команда | Синтаксис | Назначение |
|---|---|---|
| `LPUSH` | `LPUSH key value [value ...]` | добавляет элементы в начало |
| `RPUSH` | `RPUSH key value [value ...]` | добавляет элементы в конец |
| `LPOP` | `LPOP key [count]` | извлекает элементы из начала |
| `RPOP` | `RPOP key [count]` | извлекает элементы из конца |
| `LLEN` | `LLEN key` | возвращает длину списка |
| `LRANGE` | `LRANGE key start stop` | возвращает диапазон элементов |
| `LINDEX` | `LINDEX key index` | возвращает элемент по индексу |
| `LSET` | `LSET key index value` | заменяет элемент |
| `LINSERT` | `LINSERT key BEFORE|AFTER pivot value` | вставляет значение относительно опорного элемента |

Отрицательные индексы отсчитываются от конца списка.

### Множества

| Команда | Синтаксис | Назначение |
|---|---|---|
| `SADD` | `SADD key member [member ...]` | добавляет уникальные элементы |
| `SREM` | `SREM key member [member ...]` | удаляет элементы |
| `SISMEMBER` | `SISMEMBER key member` | проверяет принадлежность |
| `SMEMBERS` | `SMEMBERS key` | возвращает все элементы |
| `SCARD` | `SCARD key` | возвращает мощность множества |
| `SUNION` | `SUNION key [key ...]` | вычисляет объединение |
| `SINTER` | `SINTER key [key ...]` | вычисляет пересечение |
| `SDIFF` | `SDIFF key [key ...]` | вычисляет разность |
| `SMOVE` | `SMOVE source destination member` | переносит элемент между множествами |

Порядок элементов в ответах не гарантируется, поскольку значения хранятся в `std::unordered_set`.

### Геопространственные данные

| Команда | Синтаксис | Назначение |
|---|---|---|
| `GEOADD` | `GEOADD key lon lat member [...]` | добавляет или обновляет точки |
| `GEOPOS` | `GEOPOS key member [member ...]` | возвращает координаты |
| `GEODIST` | `GEODIST key member1 member2 [unit]` | вычисляет расстояние |
| `GEOSEARCH` | `GEOSEARCH key FROMLONLAT lon lat BYRADIUS radius unit [ASC|DESC] [COUNT n]` | ищет точки в радиусе |
| `GEOSEARCHSTORE` | `GEOSEARCHSTORE dest source FROMLONLAT lon lat BYRADIUS radius unit [ASC|DESC] [COUNT n]` | сохраняет результаты поиска |

Поддерживаемые единицы расстояния:

- `m` — метры;
- `km` — километры;
- `mi` — мили;
- `ft` — футы.

Расстояние между координатами вычисляется по формуле Хаверсина с радиусом Земли `6372.8 км`.

### Общие команды

| Команда | Синтаксис | Назначение |
|---|---|---|
| `TYPE` | `TYPE key` | возвращает тип значения |
| `DEL` | `DEL key [key ...]` | удаляет ключи |
| `EXISTS` | `EXISTS key [key ...]` | считает существующие ключи |
| `KEYS` | `KEYS pattern` | ищет ключи по шаблону |
| `FLUSHDB` | `FLUSHDB` | очищает хранилище |
| `DBSIZE` | `DBSIZE` | возвращает количество ключей |
| `MEMORY USAGE` | `MEMORY USAGE key` | возвращает оценку памяти ключа |
| `CONFIG SET` | `CONFIG SET maxmemory value` | изменяет лимит памяти |
| `CONFIG GET` | `CONFIG GET maxmemory` | возвращает текущий лимит |

## Архитектура

```text
Текстовая команда
       │
       ▼
DataBase::Execute
       │
       ├── разбиение строки на токены
       ├── нормализация имени команды
       └── поиск обработчика
               │
               ▼
    handlers_: unordered_map
               │
       ┌───────┼────────┬──────────┬───────────┐
       ▼       ▼        ▼          ▼           ▼
    String    List     Set        Geo       General
       │       │        │          │           │
       └───────┴────────┴──────────┴───────────┘
                       │
                       ▼
            unordered_map<string, Value>
```

### Модель значения

```cpp
using ValueData = std::variant<
    std::string,
    std::list<std::string>,
    std::unordered_set<std::string>,
    std::unordered_map<std::string, GeoPoint>
>;

struct Value {
    std::size_t memory_usage;
    ValueData data;
    ValueType type;
    std::optional<TimePoint> ttl;
};
```

`std::variant` позволяет хранить разные типы данных в одной таблице, не используя наследование и ручное управление памятью.

### Диспетчеризация команд

При создании `DataBase` формируется таблица:

```cpp
std::unordered_map<std::string, CommandHandler> handlers_;
```

Каждое имя связано с лямбда-обработчиком:

```cpp
handlers_["GET"] = [this](const auto& args) {
    return Get(args);
};
```

Новая команда добавляется без расширения большого `if` или `switch` в методе `Execute`.

### Результат выполнения

```cpp
using CommandResult =
    std::expected<std::string, std::string>;
```

- успешная ветвь содержит ответ команды;
- ошибочная ветвь содержит сообщение об ошибке;
- библиотечный интерфейс не зависит напрямую от `stdout` и `stderr`.

## Хранение данных

Основное хранилище:

```cpp
std::unordered_map<std::string, Value> db_;
```

Типичные оценки сложности:

| Операция | Средняя сложность |
|---|---:|
| Поиск ключа | `O(1)` |
| `SET`, `GET`, `DEL`, `EXISTS` | `O(1)` на один ключ |
| `LPUSH`, `RPUSH`, `LPOP`, `RPOP` | `O(1)` на элемент |
| `LINDEX`, `LSET` | `O(n)` |
| Операции над множествами | зависят от числа элементов |
| `GEOSEARCH` | `O(n log n)` из-за полного просмотра и сортировки |
| `KEYS` | `O(n)` по числу ключей |

## TTL

`EXPIRE` сохраняет момент истечения на основе `std::chrono::steady_clock`.

Удаление реализовано лениво:

1. команда обращается к ключу;
2. `ProccessExpiration` сравнивает текущее время с TTL;
3. просроченное значение удаляется;
4. счётчик памяти уменьшается.

`DBSIZE` и `KEYS` дополнительно проверяют несколько ключей, чтобы не учитывать истёкшие записи в результате.

Значения `TTL`:

| Результат | Значение |
|---|---|
| ключ не существует | `-2` |
| TTL не назначен | `-1` |
| TTL назначен | оставшееся число секунд |

## Контроль памяти

Лимит можно передать при запуске:

```bash
./build/labwork10 --maxmemory 64mb
```

Поддерживаемые суффиксы:

```text
b, kb, mb, gb
```

Лимит можно изменить во время работы:

```text
CONFIG SET maxmemory 128mb
```

Перед операцией, увеличивающей объём данных, вычисляется ожидаемое изменение. Если оно превышает лимит, команда отклоняется:

```text
(error) OOM command not allowed when used memory > 'maxmemory'
```

Оценка памяти учитывает длину ключей и пользовательских данных. Она предназначена для контроля относительного роста хранилища, а не для точного измерения фактически выделенной памяти STL-контейнеров.

## Требования

- компилятор с поддержкой **C++23**;
- **CMake 3.20+**;
- стандартная библиотека C++;
- подключение к интернету при первой конфигурации тестов.

Для тестирования CMake загружает **GoogleTest 1.16** через `FetchContent`.

## Использование как библиотеки

```cpp
#include "DataBase.h"

#include <iostream>

int main() {
    DataBase database;

    auto set_result = database.Execute("SET language cpp");
    auto get_result = database.Execute("GET language");

    if (get_result) {
        std::cout << *get_result << '\n';
    } else {
        std::cerr << get_result.error() << '\n';
    }
}
```

Библиотека собирается как CMake-цель:

```cmake
db_lib
```

- положительные и отрицательные индексы;
- диапазоны и вставку в список;
- уникальность элементов множества;
- объединение, пересечение и разность множеств;
- перемещение элементов между множествами;
- добавление и обновление координат;
- расчёт расстояний;
- поиск и сохранение георезультатов;
- TTL и удаление истёкших ключей;
- лимит памяти и освобождение места;
- шаблоны `KEYS`;
- общие команды базы данных;
- неверные команды и отсутствующие ключи.

- `std::optional` для TTL и лимита памяти;
- `std::unordered_map` и `std::unordered_set`;
- `std::list`;
- `std::chrono::steady_clock`;
- `std::function` и таблица обработчиков;
- лямбда-выражения;
- регулярные выражения;
- файловая организация большой библиотеки;
- CMake с несколькими поддиректориями;
- GoogleTest;
- sanitizers и CI.
